## What is new

[№ 004](/research/flight-prototype/) showed the decision core and a demo. Version 0.2.0 adds three things:

<ul class="sig-list">
  <li><strong>A bench.</strong> <Claim id="flight.bench.runs_per_host" /> runs per host, each with three replica processes on one host, the shrinking quorum against fixed TMR on the same faults.</li>
  <li><strong>F&#x2060;´ components.</strong> The core inside NASA JPL's F&#x2060;´, through a C interface that Kani proves equal to it.</li>
  <li><strong>Resets.</strong> The demo saves its state and resumes after a crash or power cut, with the same counts.</li>
</ul>

</Section>

## The cost, measured

The extra work has a price on the last replica. Upsets that hit both of its runs alike gave up to <Claim id="flight.wrong.common_mode_max" /> wrong results per run. A replica that got stuck gave <Claim id="flight.kat.wrong" />, before the periodic known-answer test caught it <Claim id="flight.kat.latency_ticks" /> ticks later. A later campaign measured how many faults that test catches at all: see <a href="https://docs.mru.space/core/bench/#kat">known-answer test coverage</a>.

Dusk, the simulator, predicts these counts. Run on the same schedules, its policy model agrees with the bench within 3 standard errors in 17 of 18 comparisons. That checks the model against the code. It does not calibrate the environment: that needs radiation or flight data.

</Section>

## Inside F&#x2060;´

Four components for F&#x2060;´ v4.4.1: RedundancyManager, HealthRegistry, ReplicaHost, and FaultInjector for tests. Every decision still comes from the Rust core. A C interface carries it, and Kani proves that its decide, mode, strike and clear functions give the core's answer.

<ul class="sig-list">
  <li><strong>Counts against the demo.</strong> On the bench schedules, 36 of 60 runs match the demo exactly. In the rest, a replica that dies is found by silence, which costs 2 correct results. Wrong results match in all 60.</li>
  <li><strong>Spares and standby.</strong> A slot can take a spare after a known-answer test, or be set aside to save power.</li>
  <li><strong>Resets.</strong> Policy, slots and cycle survive a reset.</li>
</ul>

<p style="margin-top: 16px"><Claim id="flight.fprime.unit_tests" /> unit tests and <Claim id="flight.kani.total" /> Kani proofs run on every change.</p>
